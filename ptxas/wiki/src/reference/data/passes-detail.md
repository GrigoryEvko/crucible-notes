# Validation & Lowering Pass Detail (14 phases)

> *Addresses apply to ptxas v13.0.88 (CUDA 13.0). VA base 0x400000 (non-PIE).*

Deep-dive detail for 14 high-leverage validation/lowering/analysis phases. Each phase is a 16-byte command object built by the factory `sub_C60D30`; the dispatch loop `sub_C64F70` calls vtable slot 0 (Execute), whose execute-thunk (in the `0xC5E000`-`0xC60Cxx` band) optionally calls the OptBudget gate `sub_7DDB50` and then tail-jumps to the worker or virtual-dispatches through the per-architecture profile (`Gb+0x630`) or shaderType (`Gb+0x640`). The `bin_index` is the authoritative factory/name-table index. See [Validation & Lowering Passes](../../passes/validation-and-lowering.md) for the grouped narrative.

## Per-phase key transform

### OriCheckInitialProgram (bin 0)

**Dispatch:** direct tail-jmp (mov rsi,rdi; jmp 0x7EF260). **Worker/slot:** `sub_7EF260`.

Worker sub_7EF260 gates on (ctx+0x566 & 0x0401)!=0 (testw $0x401; jne else repz ret) -- a two-bit (bit0 + bit10) verify/debug mask. When set: reads theProfile (ctx+0x630), builds a 16-byte scope record [ctx,theProfile] on stack, then runs the RAII enter/inspect/leave chain sub_7EA6C0 (enter: reads ctx->[0x110] first-inst/Gb-state, scans with packed mask 0x2080000010000001) -> sub_7EF090 (inspect: sub $0x208 frame, derefs ctx+8->[+0x848], compares a vtable slot vs 0x7D7960, walks the program node graph via call *0x8(rax)/call *0x460(rax)) -> sub_7EA8B0 (leave: ctx+8->[+0x290] teardown record pop). Read-only DAG/consistency validation (inspects, never transforms); the actual checks live in sub_7EF090. No-op in normal (non-debug) builds. NOTE: this name appears nowhere else, and the index-0 phase otherwise begins with FP16 promotion; the shipping binary prepends this double-flag-gated consistency walk ahead of FP16. Its inspect-walk semantics match a debug-DAG validation pattern (assert-on-failure). CONF: HIGH that it is debug-gated read-only validation; MEDIUM on the exact public name identity (name binding uncertain). Binary wins.

### PromoteFP16 (bin 2)

**Dispatch:** direct call (sub 0x18; lea 8(rsp),rdi; mov rsi,8(rsp); call 0x7EEB10). **Worker/slot:** `sub_7EEB10`.

Gated on ctx+1377&0x40 (HasHalfInst) AND ctx+1418&0x40 (EnableFP16PromotionPhase). Unconditionally clears HasHalfInst (ctx+1377 &= 0xBF) -- the flag is invalid from here until it is recomputed before MidExpansion. Zeroes per-vreg scratch DWORD at vreg+84 over vreg list at ctx+104 (ClearFP16DefRefByNonPromotable), calls sub_7EE4A0 (CollectDefRefForVregs), then walks inst list at ctx+272 (ip=ip->next): for nodes with type field +76==7 (DT_HALF) calls sub_7EE400 (IsFP16Promotable); if true calls sub_7EE8A0 (PromoteFP16Inst). Else-branch still clears HasHalfInst. CONF: HIGH (full FP16-promotion flow recovered from the worker body).

### AnalyzeControlFlow (bin 3)

**Dispatch:** gated direct tail-jmp (run-gate sub_7DDB50==1 + profile knob check + jmp). **Worker/slot:** `sub_781F80(ctx,0)`.

Thunk: gate sub_7DDB50(ctx)==1, then reads oriKnobs via ctx+0x680 (knob accessor guarded vs default IsKnobActive impl 0x6614A0, knob byte cmpb $0,0x4218(oriKnobs)=DISABLESOURCEORDER), then sub_781F80(ctx, esi=0). GATE PRIMITIVE: sub_7DDB50 is the OptBudget oracle (NOT raw OptLevel) -- it consults knob 499 (ORI_KNOB_OPTBUDGET) via the 72-byte knob-entry stride (entry@knobs[9]+72*499=+35928: byte+0=active, dword+8=limit @+35936, dword+12=count @+35940), returns the effective opt level *(ctx+2104=0x838) while under budget (incrementing the counter), but returns the LITERAL 1 (forced-O0 sentinel) once the budget is exhausted. Hence ret==1 (je) == the NOOPT predicate (OptLevel==0), ret>1 (jg) == optimizing. So AnalyzeControlFlow's selection predicate is (NOOPT && !IsKnobActive(DISABLESOURCEORDER)). Worker (~131 callers): a2=0 = structural non-mutating build (default); a2!=0 adds RPO loop-rotation/branch-straightening + sourceBidxMap snapshot, with self-recursion. Re-entry guard at worker head: if (ctx+1370 & 4) already set and (a2==0 or ctx+1370 & 8), bail. Builds ordered block index array at ctx+512 (running count ctx+520, written at the OP_LABEL/0x61 case), per-block predecessor list at block+128 (+0x80) and successor list at block+136 (+0x88) (intrusive edge nodes), loop header/back-edge/reachable bits packed in the block flags dword block+0x118 (per-block reset ANDs it with 0xFF78F98F). Partitions insts by walking node+8, normalizing opcode node+72 (BYTE1 & 0xCF): opcode 97(0x61)=OP_LABEL starts a region/block, branch/exit opcodes terminate. On completion: ctx+1370 = (8*(a2&1)) \| (old & 0xB3) \| 4 -- bit2(0x4) CFG-valid set always, bit3(0x8) = (a2&1) analysis-strength. CONF: HIGH (gate/offsets/bits confirmed against decompiled worker; loop-depth interval machinery MEDIUM).

### OriCreateMacroInsts (bin 9)

**Dispatch:** direct tail-jmp (mov rsi,rdi; jmp 0x19DFC20). **Worker/slot:** `sub_19DFC20`.

Worker is sub_19DFC20 (NOT sub_A112C0 -- A112C0 is idx 11 EarlyOriSimpleLiveDead, reached via the NEIGHBORING thunk 0xC5F8E0 whose own gate is ctx+0x588 bit7; do not conflate). Canonical thunk 0xC5F8D0 jumps unconditionally into sub_19DFC20 whose head gate is cmpb $0,0x564(ctx); js -- ctx+0x564 bit7 = HasTTU early-out (repz ret if clear). Walks inst list at ctx+0x110 (node->node+0x8); matches opcode class (node+0x48 & 0xCF00)==0xFC00 = OP_TTUOPEN (sequence head), with sub-class handling 0xFD00 (TTUST) / 0xFA00 (TTUMFUSE) operand legalization and the OP_MACRO dissolve path (worker 0x19DFE80) keying ==0x6D00. On match calls sub_7DD250 which allocates+zero-inits a 0x40-byte Ori def (macro) record (sets *rec=0xFFFFFFFF, +0x18=3, +0x6 &= 0xF8) and grows the per-function def table via the ctx+0x188/+0x190/+0x194 base/count/cap triple ((cap+1)>>1 geometric growth), returning a macro-index; caller loads the 8-byte slot ctx+0x188+id*8. New MACRO node spliced into the doubly-linked list (writes node+0x20/+0x28 = begin/end inst, orb 0x9c@+4, 0x20@+5, orl 0x4000@+8/+0xc, recomputes uniformity byte +0x14); emit via sub_19DFBD0 -> sub_9314F0(...,0x6D,...) (OP_MACRO-class materialize). The body is unmistakably a TTU ray-tracing macro packer (the public name does not surface the "TTU" string, but the logic does): it gates on HasTTU, scans OP_TTUOPEN, allocates+grows the next macro record (64-byte alloc + table grow), legalizes TTUST operands via inserted MOVs, sets the macro instruction range (TTUMACRO, ipBegin, ip->prev), splices constituents out, and emits the replacement. CONF: HIGH (gate ctx+0x564 bit7, opcode 0xFC00=TTUOPEN, and TTU identity all confirmed).

### OriSanitize (bin 13)

**Dispatch:** direct tail-jmp (mov rsi,rdi; jmp 0x1C64BF0). **Worker/slot:** `sub_1C64BF0`.

CORRECTION: despite the public name, sub_1C64BF0 is the compute-sanitizer instrumentation pass. Gated on byte ctx+0x584 bit7 (cmpb $0,0x584; js). Arch gate: theProfile (ctx+0x630) field +0x174 > 0x4FFF (sm-version threshold; jle bail), and (*ctx)+0x420 (sanitizer-mode name string) must be non-null. String-compares the mode (repz cmpsb) against "memcheck" (@0x21ED5FC) -> metadata-init path, and "threadsteer" (@0x1CE3D43) -> instrumentation-walk path; emitted symbol names compared vs "__cuda_sanitizer" (@0x1CE716A). __cuda_sanitizer_memcheck_{generic,global,local,malloc,readmetadata} name table @0x1D17740. Threadsteer path walks inst list (base ctx+0x170, count via ctx+0x178) keying on masked opcode (node+0x48 & 0xCF00) in {0x10,0x7D,0xB7,0x120} (load/store/atomic class), querying sub_7DFFC0 (operand-type classify) and sub_7DF3A0 (node-attribute record; flags &8 = is-memory-access / needs-instrument), then for 0xB7/0x120 dereferences an operand symbol (node+0x50, masked 0xFFFFF) via ctx+0x98 and materializes a runtime-call sequence (sub_7DAFF0 + builder 0x934630, opcode 0x91, descriptor 0x60000001), stashing node[0]->ctx+0xE8 and node+0x14->ctx+0x108. Memcheck path builds the 6-entry stack table of __cuda_sanitizer_memcheck_{generic,global,local,malloc,readmetadata} ids and runs the metadata finalizer (record dtor sub_1C64830). All four string VAs byte-verified in .rodata ("memcheck"@0x21ED5FC, "threadsteer"@0x1CE3D43, "__cuda_sanitizer"@0x1CE716A, name strings packed inline @0x1D17740). NOTE: despite the generic "sanitize" name, this pass is specifically the compute-sanitizer device instrumentation injector -- a binary-only discovery, established entirely from the disassembly and the byte-verified .rodata strings. CONF: HIGH (binary).

### ExtractShaderConstsFirst (bin 39)

**Dispatch:** gated direct tail-jmp (run-gate sub_7DDB50>1; xor esi,esi; jmp). **Worker/slot:** `sub_1C72640(ctx,0)`.

Gate sub_7DDB50>1 (OPT; OptBudget oracle), then sub_1C72640(ctx, a2=0=extract). Computes remainingConstBytes = (block-range query) - *(ctx+928); a2=0 takes the early-out unless that budget v18 > 3 (equivalently: return when (!FinalCall \|\| setupShader empty) && remainingConstBytes<4). Allocates seven stack/arena tables (teardown dtors sub_1C68B60/1C690B0/1C68BE0/1C68C60/1C68CE0/1C68D60/1C69030) plus two vreg-count bitmaps sized (numVregs+64)>>6 (sub_6E6650) backing def/ref bookkeeping + per-const-bank slot map + worklists. Runs MarkShaderConstDefs -> UnmarkLeastProfitableConstDefs -> ExtractShaderConstDefs(false) via the chain sub_1C6F590->1C6DD40->1C6A230->1C72370 (each gated on the budget and on the candidate set non-empty): reachable const-def expr trees are replicated into the priming/setup-shader region and main-shader refs rewritten to const-bank reads. a2=0 SKIPS the finalize commit sub_1C68760 (may run again). Reg ids extracted as operand & 0xFFFFFF (24-bit). CONF: HIGH.

### ExtractShaderConstsFinal (bin 59)

**Dispatch:** gated direct tail-jmp (run-gate sub_7DDB50>1; mov esi,1; jmp). **Worker/slot:** `sub_1C72640(ctx,1)`.

Same worker as First with a2=1=finalize: a2 flips two things -- it bypasses the remainingConstBytes<=3 early-out (Final must run even with no const space, to commit consts a prior pass already extracted to the setup shader) AND runs the finalize commit sub_1C68760 = FinalizeSetupShader (when setup-func id *(ctx+932)<0 it allocates the setup function via sub_1C67570/sub_1C67750, else materializes the const-bank setup insts via repeated sub_934630 binary-emit of opcodes 283/67/195/201, wiring the const-bank entry chain). On finalize with constants present (state object at (*(ctx+1664))+72: byte+59040==1 AND dword+59048!=0) and last-block terminator != opcode 188: re-runs sub_781F80 (CFG rebuild @0x1C732C1), then emits via sub_7E6090 (@0x1C732D2) and sub_A13890 (@0x1C732EE, const-bank loads); operand rewrites collected into a sub_1C69460-grown pair list, then the post-rewrite consistency check walks every setup-func block, reads each operand reg id (& 0xFFFFFF) and asserts the rewritten const-bank ref's loop-id *(v+66) == target block +164 field; mismatch (or unreached operand) -> BUG(). Finalized via sub_8E3A20. This guards const extraction never moved a ref across a loop/block boundary. CONF: HIGH.

### ConvertVTGReadWrite (bin 45)

**Dispatch:** pure virtual on target profile (mov 0x630(rsi),rdi; jmp *0xA8(*rdi)). **Worker/slot:** `profile-vtable slot +0xA8`.

Pure tail vtable dispatch on theProfile (ctx+0x630), slot +0xA8; no run-gate (always runs). Base-profile impl (base vtable VMA 0x21CDCB8, slot +0xA8) = sub_7D6BB0 (empty repz ret) -- compute/non-VTG profiles no-op. VTG-capable profiles override slot +0xA8 -> sub_8116B0, which walks the inst list, classifies operands by register class (sub_7DEB10), and rewrites vertex/tess/geometry varying input/output regs into memory READ (read-path profile slot +0x998) / WRITE (write-path slot +0x9A0) intrinsics plus opcode-0xB7 emission (sub_930910); clears OutputRegistersMaybeRead/outputRegMap. CONF: HIGH (binary base-stub 0x7D6BB0 + override 0x8116B0 confirmed).

### DoVirtualCTAExpansion (bin 46)

**Dispatch:** guarded virtual on target profile (slot+0x1C0; if==default 0x7D6DD0 repz ret else jmp). **Worker/slot:** `profile-vtable slot +0x1C0`.

Tail vtable dispatch on theProfile slot +0x1C0 with a default-impl guard: if the slot resolves to the empty base impl at 0x7D6DD0 (confirmed repz ret), skip; else tail-call. Base-profile vtable 0x21CDCB8 slot +0x1C0 = 0x7D6DD0; the two non-graphics arch profiles inspected ALSO keep +0x1C0 == 0x7D6DD0, so virtual-CTA expansion is skipped on them -- only mesh/task (amplification) profiles install a non-stub override gated on IsMeshProfile()\|\|IsTaskProfile() (\|\|IsVertexProfile in one path), then DoVirtualCTATransformation. No run-gate (ALWAYS). CONF: HIGH.

### ForwardProgress (bin 49)

**Dispatch:** pure virtual on target profile (mov 0x630(rsi),rdi; jmp *0xB8(*rdi)). **Worker/slot:** `profile-vtable slot +0xB8`.

Pure tail vtable dispatch on theProfile slot +0xB8; no run-gate (always runs); the virtual takes no Gb arg (ForwardProgress(void)). Base-profile vtable 0x21CDCB8 slot +0xB8 = sub_7D6BD0 (empty repz ret). Derived override = sub_BEE590: reads per-function flags at profile+0x587/+0x584; on the +0x584 path it scans the inst list for opcode 145 (a barrier/branch-class op) whose last-operand bit2 is clear and rewrites each via sub_9253C0(...,1), then sets a forward-progress-applied marker (ctx+0x55c=1, clears a bit at ctx+0x55a). This is the YIELD/WARPSYNC insertion (the GuaranteeForwardProgress feature: insert YIELDs and WARPSYNC as needed). Dispatch ordering: after ExpandMbarrier, before OptimizeUniformAtomic (can cause data divergence). CONF: HIGH (base-stub 0x7D6BD0 + override 0xBEE590 confirmed).

### EnforceArgumentRestrictions (bin 55)

**Dispatch:** gated virtual on target profile (run-gate sub_7DDB50>1; jmp *0xD0(*profile)). **Worker/slot:** `profile-vtable slot +0xD0`.

Gate sub_7DDB50>1 (OPT; the OptBudget oracle, see AnalyzeControlFlow row), then vtable dispatch on theProfile slot +0xD0 with args (rdi=profile, rsi=Gb, edx=0=FinalCall false). Base-profile vtable 0x21CDCB8 slot +0xD0 = sub_7D6C00 (empty repz ret). Derived override = sub_13B5C80: keys on the FinalCall arg, re-consults the OptBudget gate internally (sub_7DDB50), iterates operands and enforces operand legality -- register-class / const-bank operand limits / operand-count restrictions -- emitting opcode-0xB7 fixups (sub_930910) and reorder/spill via sub_9253C0. PAIR: late variant bin 103 LateEnforceArgumentRestrictions (vtable 0x22BE5E0, execute thunk 0xC5E880) calls the SAME slot +0xD0 with edx=1=FinalCall TRUE and NO opt-gate (ALWAYS) -- binary-proven by disasm of 0xC5E880 (mov 0x630(rsi),rdi; mov $1,edx; mov 0xD0(rax),rax; jmp). So bin 55 runs FinalCall=false under the OPT gate and bin 103 runs FinalCall=true unconditionally. CONF: HIGH (base-stub 0x7D6C00, override 0x13B5C80, both thunks confirmed).

### ExpandJmxComputation (bin 94)

**Dispatch:** direct tail-jmp (mov rsi,rdi; jmp 0x7EE060). **Worker/slot:** `sub_7EE060`.

Worker gated on ctx+0x560 & 0x40 (HasJmx; testb; jne). blockSize = MAX(profile vtable +0x820 GetInstructionSize, +0x828 GetInstOpexSize); shift = floor(log2(blockSize)) via shift loop (GetPowerOf2). Walks BBs (ctx+0x110 FirstBB / +0x128 block array); for a terminating OP_JMX (opcode 0x5E, node+0x48&0xCF00==0x5E00) whose variant word node+0x5c has JMX_SRC_INDEX bit (bit0) set: strategy selected by node+0x54 byte0 bit2 (0x4). JMX_TAB_INCBANK: reserves a const-bank jump table via profile slot +0x260 (ReserveConstantBankSlots(numLab,&bank)), emits OP_SHL #2 (lea (,r,4)) index->byte-addr, sets node+0x58:=0 then node+0x54\|=0x50000000 (sym-opd const-bank encode); the packed-by-vreg variant ORs node+0x54\|=0x10000000 / node+0x58\|=0x1000000 (MakeIndexed encoding). JMX_TAB_INCODE (cbank unavailable): emits OP_SHL by variable `shift` (profile slot +0x248), sets node+0x5c\|=4, node+0x6c:=tab\|0x60000000, node+0x70:=0; on the impl-code failure subpath also sets ctx+0x560\|=0x80 (HasJmxImplCode) and node+0x5c\|=2. Both strategies finish by clearing node+0x5c&=~1 (JMX_SRC_INDEX -> JMX_SRC_LABEL). The node fields correspond to operands opd[1] (info word = node+0x54) and opd[3] (cbank index / start-label = node+0x6c). Pre-scheduling so 32->64b addr legalization can follow; actual in-code table layout deferred to ImplJumpTablesInCode post-fixup. CONF: HIGH (full JMX-lowering flow recovered step-for-step from the worker body; log2 is a shift loop not bsr).

### FinalInspectionPass (bin 110)

**Dispatch:** chained guarded virtual on shaderType object. **Worker/slot:** `shaderType-vtable slots +0x118 then +0xC10`.

Reads shaderType obj at ctx+0x640; default-impl guard: if its vtable slot +0x60 == base sub_661310, take the equal branch -- call sub_661310's body inline: load inner pipeline obj at shaderType+0x10, call its vtable slot +0x118 (=280, sub-check/pre-check), then reload inner obj +0x10 and tail its vtable slot +0xC10 (=3088, main inspection). Otherwise (derived shaderType overrides +0x60) single direct dispatch on shaderType itself. sub_661310 (confirmed) IS exactly `(*(*(a1+16)+280))(*(a1+16)); return (*(*(a1+16)+3088))(*(a1+16));` -- the canonical two-stage inspection. The base sub_661310 is installed at slot +0x60 of several shaderType vtables (VMA 0x20274A8, 0x2027EF8, 0x202FEB8, 0x21B5010...), so those run the two-stage base inspection; specialized shaderTypes override +0x60 to bypass it. No run-gate (ALWAYS). CONF: HIGH.

### BackPropagateVEC2D (bin 116)

**Dispatch:** gated direct tail-jmp (run-gate sub_7DDB50>1; mov rdi,rbx; jmp 0x90B6A0). **Worker/slot:** `sub_90B6A0`.

Gate sub_7DDB50>1 (OPT; OptBudget oracle). Worker sub_90B6A0 gated again on ctx+0x559 & 0x40 (=ctx+1369; testb $0x40,0x559(rdi); arch/feature bit -- VEC2D back-prop enabled only when set). Allocates a 24-byte worklist control node from the per-context arena (*(ctx+16) -> vtable slot+0x18 alloc=24 bytes), stores arena back-ptr at node+16, type tag *node=2 (intrusive prev/next/parent node kind); seeds via sub_90AB90 then drains the worklist via sub_69DD70 (pop in reverse-CFG order via +8/+16 parent links) until empty, frees both nodes via sub_661750 (x2). Seed sub_90AB90 first re-derives CFG/region structure (sub_781F80/sub_763070) then iterates insts: for each whose masked opcode (node+72, BYTE1&0xCF) == 272 = OP_VEC2D with clean modifier mask (&0x603FFFF==0), resolves dest vreg id=*(node+84)&0xFFFFFF, checks vreg descriptor flags +48 (must be the paired/64-bit form), queries profile gate-fn 57 (VEC2D-legality knob), and on success (via sub_8FC870 lo/hi half identification) pushes a propagation node so the worklist walks predecessor edges BACKWARD. The attribute propagated is the even-aligned register-pair (vec2) constraint: a VEC2D consumer forces its two source vregs into an aligned consecutive pair, pushed back to the defining insts. Runs post-ScheduleInstructions and before AllocateRegisters because instruction order / pairing is only fixed after scheduling, so the pairing constraint must be re-pushed to defs before regalloc. OP_VEC2D is confirmed in the binary as the opcode that builds a 64-bit value from a lo/hi register pair; the fine-grained back-propagation predicate is inferred from this body alone. CONF: HIGH on structure/gate/worklist; MEDIUM on the exact sub-attribute flag.
